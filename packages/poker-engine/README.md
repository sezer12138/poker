# 德州扑克纯规则引擎（阶段一）

2～9 人、每人 1,000 整数筹码的无前注无限注淘汰赛。零生产依赖；状态转换返回新对象与公共事件，不读取系统时间、网络或随机源。

在仓库根目录执行（本次实测 Node v26.3.1 / npm 11.16.0；需要支持直接执行 TypeScript 的 Node 版本）：

```sh
npm ci
npm test
npm run typecheck
npm run test:exhaustive
npm run demo
```

`src/index.ts` 导出 `createTournament`、`nextHand`、`actTournament`、`legalActions`、`playerView` 及单手规则函数。`examples/simulate.ts` 展示三人比赛的调用方式，打印手号、公共事件与终局胜者。**开发演示采用固定牌序轮换，不安全，不用于真实对局；不是公平随机源或机器人策略。** 测试目录中的种子随机发生器也仅供可复现验证，不从生产入口导出。

## 输入与接入约定

引擎状态属于可信边界：调用方应保存引擎产生的状态，不能接受客户端提交的完整状态。参数入口检查合法范围、唯一性和行动；这不等于对任意伪造或被外部篡改的状态提供完整校验。服务端必须认证身份并将其绑定到 seat，验证版本及请求顺序，再调用引擎。

每手注入完整且无重复的 0～51 牌序，初始庄家也由外部注入。引擎不提供洗牌安全性或公平性证明。`playerView(hand, seat)` 提供该玩家视图，`playerView(hand, null)` 提供旁观视图；禁止向客户端广播内部状态、牌堆、烧牌或对手私牌。事件可用于公共行动广播，后续服务端需补充顺序与持久化元数据。

筹码均为有限、非负安全整数，初始每人 1,000；比赛不支持补码、重购或新增参赛者。`raiseTo.amount` 表示**本轮累计投入目标**，不是增加量。短全押不直接降低最后完整加注增量；重新开放加注按每位玩家最近行动时的下注总额及当时完整加注门槛累计计算。玩家跟注后重新开始累计，因此同一次后续短全押可能对不同玩家产生不同加注权。花色不参与比大小；边池按资格结算，未被跟上的超额退回，余下整数筹码从庄家左侧顺时针分配给并列赢家。

阶段二需要实现服务端身份鉴权、邀请与房间、WSS 协议、幂等请求与并发版本控制、状态/事件持久化及重连、服务端计时调度（引擎仅给纯超时动作）。阶段三实现安全洗牌、公平承诺核验及机器人策略；微信界面和真实设备验收按后续阶段交付。本包不包含这些功能。
