# 本地多人联机测试

项目是同一 Node 服务端托管网页、HTTP API 和 WebSocket 的多人房间。网页和原生小程序共用协议，每位玩家有独立身份，服务端决定行动是否合法，并按身份隐藏其他人的底牌。

## 同一电脑模拟两个真人

1. 安装 Node 26 或更新版本，在仓库根目录执行 `npm start`。
2. 玩家 A 用 Chrome 打开 http://127.0.0.1:8787，填写昵称，创建 0 机器人房间。
3. 玩家 B 用 Safari、另一个浏览器配置文件或独立隐私会话访问同一地址，填写不同昵称，以房间码加入。
4. 双方点击准备，由房主开始；轮流跟注、过牌、加注、弃牌，观察双方底池、公共牌、当前行动者同步。
5. 顶栏点击「语音」「音效」可分别开启；「音乐」独立控制。初次默认为关闭，设置保存在当前客户端。网页刷新后保留开启偏好并显示「待启用」，点击对应开关解锁本页播放（浏览器自动播放限制）。加注语音读出“加注到……”的本轮累计目标，全押语音读出“全押，本轮共……”的累计投入；姓名仍由文字横幅显示。

不要直接在同一浏览器配置文件中复制标签页：它们共享本地登录令牌，同一个用户的新连接会顶掉旧连接。多个普通无痕窗口也可能共享隐私会话。用不同浏览器最直观。

## 同一 Wi-Fi 下电脑与手机联机

停止原来监听 8787 的服务，然后执行：

```sh
POKER_HOST=0.0.0.0 npm start
```

在 macOS 系统设置 → 网络 → 当前连接 → 详细信息中查看电脑局域网 IP，例如 `192.168.1.23`。电脑和手机都访问 `http://192.168.1.23:8787`，分别登录，按房间码加入。邀请链接也应在这个地址下生成；`127.0.0.1` 在手机上指手机自己。

连不上时依次检查：两台设备处在同一网络、没有访客 Wi-Fi 隔离、macOS 防火墙允许 Node 入站、端口未占用、VPN 没有改变路由。`0.0.0.0` 是监听地址，不是浏览器访问地址。本命令用于可信局域网开发测试。

普通局域网 HTTP 页面可能无法使用安全上下文中的随机数 API；当前客户端会提示使用公开默认贡献。这不妨碍联机操作，但完整随机贡献验证应使用 localhost 或配置可信 HTTPS 的测试域名。

## 网页与小程序同桌

1. 用微信开发者工具导入 `apps/wechat`。后端继续运行上述开发服务。
2. 开发者工具和服务端在同一电脑时，默认 `apps/wechat/config.js` 的 localhost 地址即可；远端开发机则改为电脑可达的地址。
3. 在开发者工具本地设置中启用开发期的「不校验合法域名」选项。本地游客模式会在未配置微信登录时回退，不代表真实微信登录已验证。
4. 网页创建房间，小程序使用同一房间码加入。两端准备后开始。
5. 真机测试使用可访问的 HTTPS/WSS 测试服务，配置小程序 request/socket 域名与真实 AppID，再测试登录、前后台切换与音频。开发者工具的通过不能替代真机结果。

当前每次行动等待 5 分钟，每手结算等待 10 分钟；所有本手真人确认后立即开下一手。自动化冒烟仍通过仅开发模式的参数缩短结算等待。

## 联机验收清单

- 两个真人进入同一房间，昵称/座位各不相同；至少完成一手牌。
- 每位玩家只看到自己的底牌；摊牌后按规则亮牌。
- 一人下注，其他端立即同步投入、底池、轮次；新行动只播一次短语音。
- 同一份状态多次到达、刷新页面、断网再连不会重复补播历史语音。
- 关闭语音后仍保留筹码音效；关闭音效不影响语音；关闭音乐不影响其他声音。
- 切后台后停止发声，回来同步当前局面；结算确认能继续下一手。
- 临时断开某台设备网络再恢复，能够重连；同账号重复开桌收到顶号提示。
- 分别在桌面和手机窄屏检查操作按钮、自己的底牌和结算弹窗。

## 自动化回归

```sh
npm test
npm run typecheck
npm run smoke
node --test apps/server/test/ws.test.ts
```

`smoke` 自动启动临时服务端和独立临时存储，结束后清理。WebSocket 测试覆盖多个独立用户的订阅、广播、底牌隔离、重连、心跳与顶号；这些是实际协议连接，不是两台手机真机测试。

## 部署前仍要处理的事项

- 网页已由后端托管，网页上线需要 HTTPS/WSS 入口、反向代理、持久化及密钥配置，见 [部署说明](deploy.md)。
- **生产模式会禁用游客登录。当前网页的微信登录入口需要手动提供 code，尚不是完整的网页 OAuth 登录流程。** 不能仅切换 production 就当作正式网页产品交付；需完成面向网页的登录方案。
- 原生小程序工程已经存在，仍需真实微信登录、真机音频、分享及发布验证。
- 当前以单进程服务部署为基线。房间及 WebSocket 连接由进程持有，Postgres 持久化本身不能提供跨实例实时广播；扩容前要设计房间归属和消息分发。

## 音频资源

两端各内置 28 个短 MP3（约 140 KB 磁盘占用）：5 条中文行动语音、金额用语和中文数字片段，以及 4 种合成反馈音。可在 macOS 上用 `python3 scripts/generate-audio.py` 重建，需要系统 Tingting 语音与 ffmpeg。语音是系统合成语音，后续可替换为统一录制的真人素材。小程序采用包内文件播放，无需外部语音接口。
